# Настройка скилла «Аналитика рекламы ВБ»

Делается один раз, 15-20 минут. Дальше агент запускается фразой
«аналитика рекламы ВБ».

Файлы настроек руками писать не нужно — на каждом шаге есть готовая фраза,
которую можно сказать Claude, и он создаст файл сам.

## Шаг 0. Куда положить скилл

Папку `wb-reklama-analitika` целиком положи в `~/.claude/skills/`:

```bash
mkdir -p ~/.claude/skills
cp -r wb-reklama-analitika ~/.claude/skills/
```

Проверка: спроси Claude «какие у тебя есть скиллы?» — в ответе должен появиться
`wb-reklama-analitika`.

**Важно про Cowork.** Задача должна выполняться в режиме «На вашем компьютере»
(тумблер справа вверху в окне новой задачи), а не «В облаке». Скилл, токен и
настройки лежат на твоём компьютере, и из облачной песочницы серверы
Wildberries недоступны.

## Шаг 1. API-токен Wildberries

1. `seller.wildberries.ru` под **владельцем** аккаунта (не сотрудником).
2. Настройки → Доступ к API → Создать новый токен.
3. Категории:
   - **«Продвижение»** — обязательно (реклама, ставки)
   - **«Аналитика»** — обязательно (воронка продаж, связь рекламы с заказами)
   - Больше ничего. Лишние права — лишний риск.
4. Скопируй сразу — токен показывается один раз.

## Шаг 2. Сохрани токен

**Вариант А (Mac/Linux):**
```bash
echo 'export WB_API_TOKEN="твой_токен"' >> ~/.zshrc && source ~/.zshrc
```

**Вариант Б (работает везде, в том числе на Windows):** скажи Claude:

> Сохрани мой токен Wildberries в файл reference/token.txt в скилле
> wb-reklama-analitika: `[вставь токен]`

Проверка: «покажи первые 5 символов моего токена ВБ».

Если сделала два отдельных токена — второй (Аналитика) в `WB_STATS_TOKEN` или
`reference/token_stats.txt`. Один общий токен с обеими категориями тоже работает.

Токен не пересылать, не показывать на записи экрана, не коммитить. В
`.gitignore` он уже закрыт.

## Шаг 3. Лимиты — файл reference/limits.json

Скажи Claude:

> Создай в скилле wb-reklama-analitika файл настроек limits.json: потолок ставки
> 500 руб, менять не больше чем на 20% за раз, целевая цена заказа 300 руб,
> целевой ДРР 15%, отчёт в чат

Получится файл по образцу `reference/limits.example.json`:

```json
{
  "MAX_CPM": 500,
  "MAX_STEP_PERCENT": 20,
  "TARGET_CPO": 300,
  "TARGET_DRR": 15,
  "MIN_CPM": 100,
  "ALERT_SPEND": 1500,
  "REPORT_TO": "chat",
  "TG_BOT_TOKEN": "",
  "TG_CHAT_ID": ""
}
```

- **MAX_CPM** — потолок ставки. Агент физически не поставит выше: `stavki.py`
  откажет, даже если анализ попросит.
- **MIN_CPM** — пол ставки, ниже не опустит.
- **MAX_STEP_PERCENT** — максимум изменения за раз. 20% безопасно.
- **TARGET_CPO** — сколько готова платить за заказ (обычно 20-30% цены товара).
- **TARGET_DRR** — целевая доля рекламы в выручке, %.
- **ALERT_SPEND** — при каком дневном расходе без заказов сторож бьёт тревогу.
- **REPORT_TO** — куда слать отчёт: `"chat"`, `"telegram"` или `"both"`.

Не знаешь свои цифры — первый запуск «аналитика рекламы ВБ, только посмотри»
покажет текущие CPO и ДРР, от них и отталкивайся.

Проверка: «покажи мой limits.json и объясни каждую строку».

## Шаг 4. Telegram-доставка (по желанию, 5 минут)

Нужно для `REPORT_TO` = `telegram`/`both` и для алертов сторожа.

1. В Telegram найди `@BotFather` → `/newbot` → имя бота → получишь токен вида
   `123456:ABC-DEF...` → вставь в `TG_BOT_TOKEN`.
2. Напиши своему новому боту любое сообщение — иначе он не сможет писать первым.
3. Узнай свой chat_id: напиши боту `@userinfobot`, он ответит числом → вставь в
   `TG_CHAT_ID`.

Проверка: `python3 scripts/analiz.py --v-telegram`.

## Шаг 5. Маржа по товарам — файл reference/tovary.json

Чтобы агент считал не абстрактный CPO, а твою прибыль с каждого рекламного
заказа. Скажи Claude, по одному товару за раз:

> Добавь в настройки скилла мой товар: артикул 123456789, платье белое,
> цена 1990, закупка 620, комиссия и логистика 540

Получится файл по образцу `reference/tovary.example.json`:

```json
{
  "123456789": {"nazvanie": "Платье белое", "cena": 1990, "sebestoimost": 620, "komissiya_i_logistika": 540}
}
```

Ключ — артикул WB (nmID). Не знаешь комиссию и логистику — спроси агента:
«посчитай мою комиссию и логистику по артикулу X из последнего отчёта
реализации».

Без этого файла агент работает по `TARGET_CPO`, но язык денег
(«ты зарабатываешь / теряешь с заказа») недоступен.

## Шаг 6. Сторож 24/7 (по желанию, но это самое «вау»)

Следит за рекламой каждые 30 минут, молчит пока всё в норме, шлёт алерт в
Telegram, если кампания сливает бюджет, встала или кончился баланс. Ничего не
меняет — только сигналит. Плюс копит замеры для разбора по часам.

Mac/Linux:
```bash
crontab -e
```
строка (замени путь на свой):
```
*/30 8-23 * * * cd ~/.claude/skills/wb-reklama-analitika && python3 scripts/watchdog.py >> data/watchdog.log 2>&1
```

Нужен компьютер, который не спит днём, либо VPS.

Проверка: `python3 scripts/watchdog.py` руками — должен написать «всё в норме»
или прислать алерт.

Через день-два работы: «покажи мои мёртвые часы» — агент запустит
`watchdog.py --chasy`.

## Шаг 7. Первый запуск

Напиши в проекте: **«аналитика рекламы ВБ, только посмотри»**

Агент проверит токен, покажет кампании, свяжет рекламу с продажами и выдаст
отчёт без единого изменения. Всё адекватно — следующий запуск без
«только посмотри».

## Фразы после настройки

| Фраза | Что делает |
|---|---|
| «аналитика рекламы ВБ» | полный разбор с корректировкой ставок |
| «аналитика рекламы ВБ, только посмотри» | то же самое, но без изменений |
| «итоги недели» | вердикт: что масштабируем, что закрываем |
| «что если подниму ставку в кампании X до 400» | прогноз без изменений |
| «верни как было» | откат последних изменений |
| «покажи мои мёртвые часы» | в какие часы уходит бюджет без заказов |
| «почини вызов по документации» | починка после обновления API WB |

## Частые проблемы

- **401** — токен не тот, истёк или создан без нужных категорий. Пересоздай.
- **403** — не отмечена категория «Продвижение» или «Аналитика».
- **429** — лимит запросов, агент сам подождёт 60 секунд.
- **400/404 на рабочем методе** — WB обновил API. Скажи агенту: «почини вызов по
  документации dev.wildberries.ru».
- **Не могу достучаться до серверов WB** — задача Cowork запущена в облаке.
  Переключи её в режим «На вашем компьютере».
- **Ставки в кабинете не изменились** — API применяет с задержкой до пары минут.
- **Пустая статистика за сегодня** — WB отдаёт данные текущего дня с задержкой,
  смотри вчерашний период.

## Безопасность

- Токен = доступ к рекламному бюджету. Не пересылать, не светить на скриншотах,
  пересоздавать раз в 3 месяца.
- Агент не останавливает кампании, не меняет дневные бюджеты и не превышает
  `MAX_CPM`. Это зашито и в правила `SKILL.md`, и в проверки `scripts/stavki.py`,
  и в сам набор методов API: вызовов остановки кампании в коде просто нет.
- Каждое изменение пишется в `data/changes.jsonl` со старым значением — «верни
  как было» работает всегда.
